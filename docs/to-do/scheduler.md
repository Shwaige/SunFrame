# 持续轮询调度器待办

## 目标

新增一个常驻调度器，让脚本不再只是一次性执行，而是按账号持续轮询。每个账号独立记录下一次执行时间，到点后自动执行对应模块。

## 核心逻辑

- 以账号为调度单位，每个账号独立维护 `next_run_at`。
- 启动后常驻运行，不做固定高频全量请求。
- 每轮只执行已经到期的账号。
- 每个账号执行完成后，根据模块结果重新计算下一次执行时间。
- 不同账号可以有不同的下一次执行时间。
- 脚本重启后应恢复上次调度状态。

## 建议命令

```bash
python3 -m ygmc.cli scheduler accounts.batch.txt
```

## 状态文件

建议新增本地状态文件：

```text
.ygmc_schedule.json
```

示例结构：

```json
{
  "shwaige": {
    "next_run_at": "2026-05-28T22:30:00+08:00",
    "last_run_at": "2026-05-28T12:30:00+08:00",
    "reason": "作物成熟",
    "last_result": "成功"
  }
}
```

## 模块调度策略

### self-op

- 后续根据作物或动物成熟时间计算下一次执行。
- 如果种植了 10 小时成熟的作物，则设置 `next_run_at = 当前时间 + 10小时`。
- 如果无法解析成熟时间，使用默认兜底间隔。

### friends-op

- 使用固定短周期补扫。
- 初始建议间隔：10 到 30 分钟。
- 失败时使用较短重试间隔。

### sign / activity / sunshine

- 使用每日周期。
- 每天至少执行一次。
- 可统一挂在账号每日首次运行时执行。

## 失败处理

- 单个账号失败不能影响其他账号。
- 失败账号设置短重试间隔，例如 5 到 10 分钟。
- 失败信息写入 `last_result`。
